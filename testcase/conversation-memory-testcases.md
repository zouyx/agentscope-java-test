# AgentScope Java 多轮会话记忆模块测试用例设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 被测项目 | [agentscope-ai/agentscope-java](https://github.com/agentscope-ai/agentscope-java) |
| 目标版本 | `2.0.0`（与本仓库 `pom.xml` 中的 `agentscope.version` 一致） |
| 被测模块 | Agent 的多轮会话与记忆（Conversation Memory） |
| 测试级别 | 用户视角端到端集成测试 |
| 测试类 | `agentscope-e2e-tests/src/test/java/io/agentscope/e2e/ConversationMemoryIT.java` |
| 文档状态 | 已实现 |

## 2. 选择该模块的原因

本仓库现有用例覆盖了真实模型调用、流式响应以及 Java 工具调用，但没有验证 Agent
能否在连续调用中保留、隔离和使用会话上下文。记忆能力是构建多轮 Agent 的关键用户路径，
其故障通常不会表现为请求异常，而是表现为 Agent 忘记信息、会话间串数据或重置无效，
因此需要独立的行为测试。

测试设计已由 `ConversationMemoryIT` 实现，不修改生产代码、Maven 依赖或 CI 配置。
当前实现依赖 `ReActAgent` 在同一实例上的公开多轮调用行为，并通过新建 Agent 表达独立会话和
重置语义；测试不直接构造、注入或检查 Memory 实现对象。

## 3. 测试目标

1. 验证同一个 Agent 实例在后续调用中可以使用先前轮次提供的信息。
2. 验证两个 Agent（或两个独立会话）的记忆互不泄漏。
3. 验证清空或重建会话后，旧上下文不再影响回答。
4. 验证记忆中保留了正确的角色和轮次顺序，而不是仅能命中某个关键词。
5. 验证无关的中间轮次不会覆盖或截断此前保存的会话信息。
6. 保持用例可在当前 Ollama E2E 环境中执行，且不依赖外部数据库或云服务。

## 4. 范围与非目标

### 4.1 范围内

- AgentScope Java `2.0.0` 对外公开的 Agent 多轮调用行为。
- 基于当前测试基类所配置的 Ollama 模型执行真实推理。
- 会话写入、读取、隔离以及清理后的可观察行为。
- 测试失败时提供足以定位问题的断言消息。

### 4.2 范围外

- Memory 内部实现类的白盒单元测试。
- Redis、数据库或其他持久化后端。
- 跨 JVM 重启后的持久化恢复。
- 大规模并发、容量上限、性能以及 token 裁剪策略。
- 对自然语言回复全文做完全相等比较。

## 5. 测试环境与前置条件

1. Java 17、Maven 和 Docker 可用。
2. Ollama 服务监听 `OLLAMA_BASE_URL`，默认模型为 `ollama:qwen3:0.6b`；可通过
   `E2E_MODEL_ID` 覆盖。
3. 使用 Maven `e2e` profile 运行 Failsafe 集成测试。
4. `ReActAgent.call(...)` 在同一 Agent 实例上保留先前轮次，并在阻塞完成后返回可读取文本的
   最终 `Msg`。
5. TC-MEM-003 通过丢弃旧 Agent 并创建新 Agent 表达开始新会话的公开用户路径，不把该用例
   描述为调用记忆清空 API，也不通过反射或内部字段实现重置。

## 6. 通用测试策略

- 使用随机生成且低歧义的会话秘密，例如 `ORBIT-7319`，避免模型凭常识猜中答案。
- 系统提示要求回答固定格式，减少小模型输出波动；断言只检查协议标记和关键 token。
- 每个用例创建自己的 Agent/Memory，不共享静态可变状态。
- 每个调用设置 60 秒超时；模型请求或响应为 `null` 时立即失败。
- 记忆验证至少包含两轮输入，且回忆问题本身不重复秘密值。
- 对“应当忘记”的场景，要求回复固定标记 `UNKNOWN`，并同时断言回复不包含旧秘密。

## 7. 测试用例

### TC-MEM-001：同一会话可以回忆先前轮次

**优先级：** P0

**目的：** 验证一轮写入的用户信息可以被同一 Agent 的后续调用读取。

**步骤：**

1. 创建带会话记忆的 Agent，系统提示约定：知道代号时仅回复
   `CODE=<代号>`，不知道时回复 `UNKNOWN`。
2. 第一轮发送：`请记住我的项目代号是 ORBIT-7319，仅确认收到。`
3. 等待第一轮完整结束，确认返回了非空响应。
4. 第二轮发送：`我的项目代号是什么？`
5. 收集第二轮最终回复。

**预期结果：**

- 两次调用都正常完成且结果非空。
- 第二轮回复包含 `CODE=ORBIT-7319`。
- 第二轮不应回复 `UNKNOWN`。

### TC-MEM-002：独立会话之间不会泄漏记忆

**优先级：** P0

**目的：** 验证记忆的作用域正确，防止用户或会话之间的数据串扰。

**步骤：**

1. 创建相互独立的 Agent A 和 Agent B；二者使用相同模型及系统提示，但不共享 Memory。
2. 向 Agent A 发送：`请记住我的项目代号是 ORBIT-7319，仅确认收到。`
3. 不向 Agent B 提供任何代号，直接询问 Agent B：`我的项目代号是什么？`
4. 再询问 Agent A：`我的项目代号是什么？`

**预期结果：**

- Agent B 回复包含 `UNKNOWN`，且不包含 `ORBIT-7319`。
- Agent A 回复包含 `CODE=ORBIT-7319`。
- 两个 Agent 的请求均无异常，避免把模型或环境故障误判为成功隔离。

### TC-MEM-003：重置会话后旧信息不可见

**优先级：** P1

**目的：** 验证清空记忆或开始新会话能够可靠地结束旧上下文生命周期。

**步骤：**

1. 创建 Agent，并写入代号 `ORBIT-7319`。
2. 在重置前询问代号，先确认回复包含 `CODE=ORBIT-7319`，证明信息确实已写入。
3. 丢弃旧 Agent，并创建一个使用相同模型和系统提示的新 Agent，以开始独立的新会话。
4. 在重置后的 Agent 中询问：`我的项目代号是什么？`

**预期结果：**

- 重置前能够正确回忆代号。
- 重置后回复包含 `UNKNOWN`，且不包含 `ORBIT-7319`。
- 重置操作本身不抛出异常，重置后的 Agent 仍可正常响应。

### TC-MEM-004：多轮更新保留角色与时间顺序

**优先级：** P1

**目的：** 验证记忆按会话顺序提供消息，最新的用户更正可以覆盖旧值。

**步骤：**

1. 第一轮告知：`项目代号是 ORBIT-7319。`
2. 第二轮更正：`刚才的代号已作废，新代号是 NOVA-4826。`
3. 第三轮询问：`当前有效的项目代号是什么？`

**预期结果：**

- 最终回复包含 `CODE=NOVA-4826`。
- 最终回复不把 `ORBIT-7319` 声明为当前代号。
- 所有轮次均由同一会话按顺序完成。

### TC-MEM-005：无关中间轮次不会丢失已有记忆

**优先级：** P1

**目的：** 验证 Agent 不仅能回忆紧邻的上一轮消息，在处理一轮无关任务后仍能使用更早的会话信息。

**步骤：**

1. 第一轮告知 Agent 一个随机项目代号。
2. 第二轮要求 Agent 计算 `7 + 5`，并确认该轮正常返回 `12`。
3. 第三轮询问当前项目代号。

**预期结果：**

- 无关的计算轮次能够正常完成，证明会话确实向前推进。
- 第三轮回复包含第一轮保存的随机项目代号。
- 第三轮不回复 `UNKNOWN`，无关任务不会覆盖已有记忆。

## 8. 当前实现结构

`ConversationMemoryIT` 已复用 `E2eTestSupport` 中的模型配置，并以私有辅助方法构造带固定
系统提示的 Agent、阻塞获取最终回复以及生成测试秘密。任何后续用例均不应把某个用例的 Agent
或会话相关可变对象放到静态字段中。

实现时用 JUnit 5 的 `@Test` 和 `@Timeout(60)`；测试类名以 `IT` 结尾，使其只在现有
Failsafe `e2e` profile 下运行。断言应输出实际模型文本，方便 CI 失败诊断。

建议用例方法名：

- `shouldRecallFactFromPreviousTurn`
- `shouldIsolateMemoryBetweenAgents`
- `shouldForgetFactAfterConversationReset`
- `shouldUseLatestCorrectionInConversationOrder`
- `shouldRetainFactAcrossUnrelatedConversationTurn`

## 9. 运行方式

仅运行记忆模块用例：

```bash
mvn -B -pl agentscope-e2e-tests -am verify -Pe2e \
  -Dit.test=ConversationMemoryIT
```

运行全部 E2E 用例：

```bash
mvn -B -pl agentscope-e2e-tests -am verify -Pe2e
```

## 10. 通过标准

- TC-MEM-001 至 TC-MEM-003 必须通过；TC-MEM-004 和 TC-MEM-005 作为多轮语义回归用例也应纳入 CI。
- 同一提交在相同模型与环境下连续运行三次，不出现由回复措辞导致的偶发失败。
- 用例只能通过公开 API 验证行为，不能读取 Memory 私有字段或依赖实现细节。
- 失败日志能够区分模型未响应、记忆未写入、会话泄漏以及重置无效。

## 11. 风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| 小模型不严格遵守格式 | 使用短提示、唯一 token 和包含/不包含断言，不比较完整句子 |
| 模型偶然猜中秘密 | 每次运行生成随机高熵秘密，不使用姓名、城市等常识值 |
| 流式消息中间态被误当最终结果 | 实现前确认 `call(...)` 的发布语义，统一提取完整最终回复 |
| Agent 的多轮行为发生变化 | 通过同一 Agent 的连续公开调用验证，并记录升级前后的可观察差异 |
| 测试之间共享状态 | 每个测试独立创建 Agent，并禁止静态可变会话状态 |
| 没有公开的会话清空接口 | 以全新 Agent 验证新会话语义，并在用例名称和文档中明确说明 |

# AgentScope Java 工具调用测试用例设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 被测项目 | [agentscope-ai/agentscope-java](https://github.com/agentscope-ai/agentscope-java) |
| 目标版本 | `2.0.0` |
| 被测模块 | `Toolkit`、`@Tool` 与 `@ToolParam` 的 Java 工具注册和 Agent 调用路径 |
| 测试级别 | 用户视角端到端集成测试 |
| 关联自动化 | `agentscope-e2e-tests/src/test/java/io/agentscope/e2e/ToolCallingIT.java` |
| 文档状态 | 已实现 |

## 2. 测试目标与范围

验证开发者把带 `@Tool` / `@ToolParam` 的普通 Java 方法注册到 `Toolkit`，并将其传入
`ReActAgent` 后，用户请求可以触发正确的工具、以正确参数执行一次、并把业务结果返回给用户。
同时覆盖未知工具和工具执行异常这两类高风险失败。验证通过公开注解、工具副作用、返回 `Msg`
及公开异常完成，不访问 Agent 的内部推理轨迹。

通用前置条件：Ollama 与指定模型可用；工具对象在每个用例内新建，用 `AtomicInteger` 或等价的
线程安全计数器记录调用次数；单次真实模型请求的超时为 60 秒。

## 3. 测试用例

### TC-TOOL-001：Agent 使用已注册 Java 工具并返回计算结果

| 项目 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 用户目标 | 为 Agent 注册加法工具后，获得由该工具计算的结果。 |
| 前置条件 | 模型支持工具调用；`add_numbers(a, b)` 已通过 `Toolkit.registerTool` 注册。 |
| 自动化状态 | 已由 `ToolCallingIT.shouldExecuteJavaTool` 覆盖。 |

**步骤：**

1. 声明 `@Tool(name = "add_numbers")` 方法，参数以 `@ToolParam(name = "a")` 和 `b` 标记，方法
   返回 `a + b`，并在执行时递增计数器。
2. 将工具注册到新 `Toolkit`，用该 Toolkit 创建 `ReActAgent`；系统提示要求使用请求的工具并
   输出 `RESULT=<tool result>`。
3. 发送明确要求调用 `add_numbers(a=17, b=25)` 的用户消息，并等待结果。
4. 检查工具计数和最终文本。

**预期结果：** 工具恰好执行一次，接收到 `17` 与 `25`，最终非空回复包含 `42`（推荐包含
`RESULT=42`）。不应由模型直接猜算结果来替代工具执行。

**失败诊断：** 调用次数为零通常表示工具未注册、工具元数据不可见或模型未遵循指令；次数大于一
是副作用重复风险；参数/结果错误需同时记录工具实际参数与模型最终文本。

### TC-TOOL-002：多个工具中选择与用户意图匹配的工具

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 注册多个工具时，Agent 不会执行无关且有副作用的工具。 |
| 前置条件 | 注册 `add_numbers` 与一个记录调用次数的无关工具，例如 `send_notification`。 |
| 自动化状态 | 已由 `ToolCallingIT.shouldSelectRequestedToolWithoutCallingUnrelatedTool` 覆盖。 |

**步骤：**

1. 为两个工具设置不歧义的名称和描述；无关工具仅在内存中记录调用，不发送真实通知。
2. 请求“仅调用 add_numbers，a=17、b=25，不要发送通知”。
3. 等待完整结果并读取两个工具的调用计数、参数与最终文本。

**预期结果：** 加法工具恰好一次且参数正确；无关工具零次；回复含 `42`。本用例以无外部副作用的
替身工具验证选择行为，不能真的发送邮件、消息或修改生产数据。

**失败诊断：** 无关工具被调用属于高优先级的权限/工具选择风险；加法工具未调用应检查模型能力、
工具描述和注册过程；两者均未调用而模型直接回答也必须失败。

### TC-TOOL-003：工具抛出业务异常时向用户路径明确失败

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 工具执行失败时，应用不会把操作伪装成成功，调用方能得到可处理的失败。 |
| 前置条件 | 注册一个被调用即抛出受控 `IllegalStateException` 的内存测试工具。 |
| 自动化状态 | 已由 `ToolCallingIT.shouldReportToolFailureWithoutClaimingSuccess` 覆盖。 |

**步骤：**

1. 创建系统提示，要求调用该工具；发送无歧义请求。
2. 在超时内观察 `call(...)` 的最终结果或错误，并记录工具调用次数与已脱敏异常摘要。
3. 若框架将异常编排为模型可见的错误消息，继续检查最终文本不包含成功协议标记。

**预期结果：** 工具调用可被观测到一次；调用方收到异常，或收到明确的失败结果；不得出现
`RESULT=SUCCESS` 等成功标记，也不得无限等待。

**失败诊断：** 工具未调用说明前置条件没有成立；异常被吞掉并产生成功回复是 SDK 用户风险；超时
表明错误终止或资源释放路径需要专项排查。

### TC-TOOL-004：未知工具请求不会执行任何已注册工具

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 用户目标 | 用户要求不存在的工具时，不会误触发名称相近的已注册操作。 |
| 前置条件 | 已注册至少一个有调用计数的工具，用户请求的工具名确认未注册。 |
| 自动化状态 | 已由 `ToolCallingIT.shouldNotInvokeRegisteredToolForUnknownToolRequest` 覆盖。 |

**步骤：**

1. 请求调用不存在的 `delete_everything`，同时明确禁止替代操作。
2. 等待结束，检查所有实际工具的调用计数和返回/异常。

**预期结果：** 所有已注册工具调用次数为零；请求得到明确拒绝或失败，不把任一替代操作描述为完成。

**失败诊断：** 任意已注册工具被调用都是工具名称解析或安全边界风险；若模型自行编造完成结果，
应作为提示与工具结果区分问题记录。

## 4. 清理与通过标准

工具测试只能操作内存计数器和临时数据；结束后丢弃 Toolkit、Agent 与工具对象。TC-TOOL-001
必须稳定通过，且 CI 报告应在失败时输出调用次数、参数、模型标识和最终文本摘要。TC-TOOL-002
至 TC-TOOL-004 在模型支持工具调用的环境中作为回归集执行。

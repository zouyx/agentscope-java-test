# AgentScope Java 基础模型调用测试用例设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 被测项目 | [agentscope-ai/agentscope-java](https://github.com/agentscope-ai/agentscope-java) |
| 目标版本 | `2.0.0`（与本仓库 `pom.xml` 的 `agentscope.version` 一致） |
| 被测模块 | `ReActAgent` 的模型配置与同步调用用户路径 |
| 测试级别 | 用户视角端到端集成测试 |
| 关联自动化 | `agentscope-e2e-tests/src/test/java/io/agentscope/e2e/ModelSmokeIT.java` |
| 文档状态 | TC-MODEL-001 已实现；其余为扩展回归设计 |

## 2. 测试目标与范围

验证 Java 用户按公开 API 创建 `ReActAgent`、指定模型并发送 `UserMessage` 后，可以取得有用的
`Msg` 文本结果；同时覆盖最常见的模型配置和服务不可用故障。测试不验证模型回答的文采或
框架内部调度实现，也不使用 mock 替代 P0 的真实模型调用。

通用前置条件：Java 17、Maven、Docker 与可访问的 Ollama 已就绪；`E2E_MODEL_ID` 指向已下载
模型（默认 `ollama:qwen3:0.6b`）。所有模型调用超时上限为 60 秒，提示词采用可检查的
`E2E_OK` 等协议标记。

## 3. 测试用例

### TC-MODEL-001：最小配置可完成一次模型调用

| 项目 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 用户目标 | 用模型标识和系统提示创建 Agent，并获得一次可用回答。 |
| 前置条件 | Ollama 可达，指定模型已下载。 |
| 自动化状态 | 已由 `ModelSmokeIT.shouldCallRealModel` 覆盖。 |

**步骤：**

1. 使用 `ReActAgent.builder()` 设置名称、简短系统提示与 `E2E_MODEL_ID`。
2. 构造包含 `Reply with the token: E2E_OK` 的 `UserMessage` 并调用 `agent.call(...).block()`。
3. 在 60 秒内取得返回的 `Msg` 与 `getTextContent()`。

**预期结果：** 返回对象和文本均非空，文本包含 `E2E_OK`。调用不抛出异常，且不依赖 AgentScope
内部类或私有字段。

**失败诊断：** 无法连接或模型未下载通常是环境问题；有返回但遗漏标记通常是模型指令遵循问题；
在环境预检通过后返回空值、异常或超时，则应记录为 SDK 用户路径问题。

### TC-MODEL-002：独立请求获得各自对应的可观察结果

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 创建多个独立 Agent 处理不同请求时，每个请求获得与自身输入对应的结果。 |
| 前置条件 | 同 TC-MODEL-001。 |

**步骤：**

1. 创建两个独立 Agent，系统提示均要求仅回显 `TOKEN=<用户给出的 token>`。
2. 分别向两个 Agent 发送携带不同随机 token 的请求；每次等待完整 `Msg` 返回。
3. 分别读取两个返回文本。

**预期结果：** 两次结果非空，第一个结果含第一个 token，第二个结果含第二个 token，且第二个结果
不以第一个 token 作为本次协议结果。用例不要求精确匹配完整自然语言。

**失败诊断：** 一个 Agent 返回另一个请求的 token 时，优先检查调用方是否错误复用了消息、Agent 或
订阅；公共 API 输入正确且环境稳定时，作为请求关联/会话隔离回归跟踪。

### TC-MODEL-003：不可用模型配置给出可诊断的失败

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 配置不存在的模型时，能在限定时间内收到异常而非永久等待或静默空成功。 |
| 前置条件 | Ollama 本身可达；选取一个确认未下载的随机模型标识。 |

**步骤：**

1. 以不存在的 `ollama:<随机模型名>` 创建 Agent。
2. 发送最小文本请求，并在 60 秒内等待完成或失败。
3. 捕获公共 API 向调用方传播的异常并记录异常类型、消息及模型标识（不得记录密钥）。

**预期结果：** 调用以异常结束，不返回被误判为成功的空 `Msg`；异常或其根因能表明模型/服务请求失败。

**失败诊断：** 若测试模型实际已存在，应重新生成未下载名称；超时说明诊断与资源释放路径存在风险；
无错误地返回空成功则是严重的 SDK 行为问题。

## 4. 清理与通过标准

测试完成后丢弃 Agent 与返回对象，不持久化用户消息。TC-MODEL-001 必须在支持的默认模型上稳定
通过；TC-MODEL-002 和 TC-MODEL-003 的失败日志须包含实际响应或已脱敏异常摘要、模型标识和
最小复现命令。

# AgentScope Java 基础模型调用测试用例设计

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 被测项目 | [agentscope-ai/agentscope-java](https://github.com/agentscope-ai/agentscope-java) |
| 目标版本 | `2.0.0`（与本仓库 `pom.xml` 的 `agentscope.version` 一致） |
| 被测模块 | `ReActAgent` 的模型配置与同步调用用户路径 |
| 测试级别 | 用户视角端到端集成测试 |
| 关联自动化 | `ModelSmokeIT`、`ModelResilienceIT` |
| 文档状态 | 已实现 |

## 2. 测试目标与范围

验证 Java 用户按公开 API 创建 `ReActAgent`、指定模型并发送 `UserMessage` 后，可以取得有用的
`Msg` 文本结果；同时覆盖最常见的模型配置和服务不可用故障。测试不验证模型回答的文采或
框架内部调度实现，也不使用 mock 替代 P0 的真实模型调用。

通用前置条件：Java 17、Maven、Docker 与可访问的 Ollama 已就绪；`E2E_MODEL_ID` 指向已下载
模型（默认 `ollama:qwen3:0.6b`）。所有模型调用超时上限为 60 秒，提示词采用可检查的
`E2E_OK` 等协议标记。

## 3. 测试用例

### TC-MODEL-001：最小配置可完成一次模型调用

| 项目 | 内容 |
| --- | --- |
| 优先级 | P0 |
| 用户目标 | 用模型标识和系统提示创建 Agent，并获得一次可用回答。 |
| 前置条件 | Ollama 可达，指定模型已下载。 |
| 自动化状态 | 已由 `ModelSmokeIT.shouldCallRealModel` 覆盖。 |

**步骤：**

1. 使用 `ReActAgent.builder()` 设置名称、简短系统提示与 `E2E_MODEL_ID`。
2. 构造包含 `Reply with the token: E2E_OK` 的 `UserMessage` 并调用 `agent.call(...).block()`。
3. 在 60 秒内取得返回的 `Msg` 与 `getTextContent()`。

**预期结果：** 返回对象和文本均非空，文本包含 `E2E_OK`。调用不抛出异常，且不依赖 AgentScope
内部类或私有字段。

**失败诊断：** 无法连接或模型未下载通常是环境问题；有返回但遗漏标记通常是模型指令遵循问题；
在环境预检通过后返回空值、异常或超时，则应记录为 SDK 用户路径问题。

### TC-MODEL-002：独立请求获得各自对应的可观察结果

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 创建多个独立 Agent 处理不同请求时，每个请求获得与自身输入对应的结果。 |
| 前置条件 | 同 TC-MODEL-001。 |
| 自动化状态 | 已由 `ModelSmokeIT.shouldKeepIndependentModelRequestsAssociatedWithTheirInputs` 覆盖。 |

**步骤：**

1. 创建两个独立 Agent，系统提示均要求仅回显 `TOKEN=<用户给出的 token>`。
2. 分别向两个 Agent 发送携带不同随机 token 的请求；每次等待完整 `Msg` 返回。
3. 分别读取两个返回文本。

**预期结果：** 两次结果非空，第一个结果含第一个 token，第二个结果含第二个 token，且第二个结果
不以第一个 token 作为本次协议结果。用例不要求精确匹配完整自然语言。

**失败诊断：** 一个 Agent 返回另一个请求的 token 时，优先检查调用方是否错误复用了消息、Agent 或
订阅；公共 API 输入正确且环境稳定时，作为请求关联/会话隔离回归跟踪。

### TC-MODEL-003：不可用模型配置给出可诊断的失败

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 配置不存在的模型时，能在限定时间内收到异常而非永久等待或静默空成功。 |
| 前置条件 | Ollama 本身可达；选取一个确认未下载的随机模型标识。 |
| 自动化状态 | 已由 `ModelSmokeIT.shouldFailClearlyForUnavailableModel` 覆盖。 |

**步骤：**

1. 以不存在的 `ollama:<随机模型名>` 创建 Agent。
2. 发送最小文本请求，并在 60 秒内等待完成或失败。
3. 捕获公共 API 向调用方传播的异常并记录异常类型、消息及模型标识（不得记录密钥）。

**预期结果：** 调用以异常结束，不返回被误判为成功的空 `Msg`；异常或其根因能表明模型/服务请求失败。

**失败诊断：** 若测试模型实际已存在，应重新生成未下载名称；超时说明诊断与资源释放路径存在风险；
无错误地返回空成功则是严重的 SDK 行为问题。

### TC-MODEL-004：错误模型配置矩阵给出有界且可诊断的失败

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 用户目标 | 面对模型标识、地址、鉴权、限流、服务端和响应协议错误时，快速定位配置或服务问题。 |
| 前置条件 | 模型标识校验使用公开的字符串配置 API；HTTP 场景使用测试进程内、仅监听回环地址的可控 Ollama 协议服务。 |
| 自动化状态 | 已由 `ModelSmokeIT.shouldReportDiagnosableFailuresForInvalidModelConfiguration` 参数化矩阵覆盖。 |

**覆盖矩阵：** 空模型 ID、缺失 provider 前缀、未知 provider、格式错误的 base URL、HTTP
401/403/429/500/503、连接成功但不响应、malformed JSON，以及缺少消息内容的不完整协议响应。

**步骤：**

1. 对标识错误，通过 `ReActAgent.builder().model(String)` 创建 Agent 并发起最小调用。
2. 对传输和协议错误，通过公开 `OllamaChatModel` builder 指向本地模拟服务；设置 500 ms 的连接、
   读取和写入超时，再通过模型的公开流式调用 API 发起请求，避免 Agent 层重试掩盖单次协议故障。
3. 对每一行在 5 秒调用期限和 10 秒用例期限内捕获异常，并汇总公开异常的 cause chain。

**预期结果：** 每一行均以异常结束，不能返回空的成功结果；异常链非空，并至少包含与当前场景
对应的模型/provider、URL、HTTP 状态、超时、JSON 解析或响应内容诊断。各场景使用独立的本地服务，
状态码和响应体不依赖外部模型服务。

**失败诊断：** 标识和 URL 行失败通常属于用户配置；401/403 属于鉴权，429 属于限流，500/503
属于服务端；超时属于服务可达但无响应；JSON/字段缺失属于协议兼容性。任一行永久等待、无关异常或
空成功均作为 SDK 可诊断性缺陷记录。

**清理：** 每个 HTTP 场景在 `finally` 中停止回环模拟服务；不创建容器、不访问真实模型，也不记录
凭据或请求中的用户数据。

## 4. 清理与通过标准

### TC-MODEL-005：限流响应按有界退避重试并恢复

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 用户目标 | 模型服务返回带 `Retry-After` 的 429 后，通过公开重试配置等待并再次调用。 |
| 前置条件 | 启动仅绑定本机随机端口的可控 Ollama 协议服务；首次返回 429，第二次返回有效结果。 |
| 自动化状态 | 已由 `ModelResilienceIT.shouldRespectRetryAfterForRateLimitedModelRequest` 覆盖。 |

**步骤：** 配置最多 2 次尝试和 1 秒退避；调用 Agent；记录请求次数、总耗时及最终文本。

**预期结果：** 首次 429 后不会立即重放；只重试一次；最终返回非空 `RESULT=OK`，总耗时不短于
允许调度误差后的退避下限。服务和执行器在用例结束时关闭。

### TC-MODEL-006：短暂服务故障的重试次数有界

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 用户目标 | 持续 503 时，请求在配置次数内停止并保留可诊断错误。 |
| 前置条件 | 本地可控服务对每次调用返回包含临时故障说明的 503。 |
| 自动化状态 | 已由 `ModelResilienceIT.shouldBoundRetriesForTransientModelFailure` 覆盖。 |

**步骤：** 配置最多 3 次尝试和短退避；发起调用；捕获最终异常并检查服务计数。

**预期结果：** 总调用次数恰好为 3；调用以异常而非空成功结束；异常 cause chain 保留 503 或服务
故障诊断。失败诊断应区分服务持续不可用和 SDK 超出重试上限。

测试完成后丢弃 Agent 与返回对象，不持久化用户消息。TC-MODEL-001 必须在支持的默认模型上稳定
通过；TC-MODEL-002 和 TC-MODEL-003 的失败日志须包含实际响应或已脱敏异常摘要、模型标识和
最小复现命令。

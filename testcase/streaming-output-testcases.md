## 1. 文档信息

| 项目 | 内容 |

| 目标版本 | `2.0.0` |

| 测试级别 | 用户视角端到端集成测试 |
| 关联自动化 | `agentscope-e2e-tests/src/test/java/io/agentscope/e2e/StreamingIT.java` |

## 2. 测试目标与范围

验证应用通过公开的 reactive `call(...)` 返回值订阅消息时，能在请求完成前或完成过程中观察到至少
一个可用文本消息，并能正确处理空文本与错误终止。这里的“流式”以用户可订阅到消息发布为准，
不假定内部 chunk 切分数量、token 边界或具体网络实现。

通用前置条件：Ollama 与 `E2E_MODEL_ID` 已就绪，所有订阅在 60 秒内结束；每个用例使用独立
Agent 和线程安全的事件收集容器。

## 3. 测试用例

### TC-STREAM-001：订阅调用结果可接收非空文本事件

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 在等待请求结束时，界面或调用方能够消费 Agent 发布的文本。 |
| 前置条件 | Ollama 可达，模型已下载。 |
| 自动化状态 | 已由 `StreamingIT.shouldStreamModelOutputThroughAgent` 覆盖。 |

**步骤：**

1. 创建系统提示为简短纯文本回复的 Agent。
2. 发送“Write the numbers 1, 2, and 3.”，对 `agent.call(...)` 注册 `doOnNext` 收集每个 `Msg`。
3. 调用 `then().block()` 等待流正常结束。
4. 检查消息列表及每项的 `getTextContent()`。

**预期结果：** 至少发布一条消息，且至少一条消息含非空白文本；流在超时前正常完成。断言不要求
恰好三个 chunk，也不要求单条消息包含完整回答。

**失败诊断：** 完全无事件但连接正常时，优先检查 AgentScope 的发布路径；只有空事件时记录实际
事件文本；超时或连接错误先按 Ollama 环境故障排查。

### TC-STREAM-002：消费者可按发布顺序拼接文本而不丢失内容

| 项目 | 内容 |
| --- | --- |
| 优先级 | P1 |
| 用户目标 | 应用将每个非空文本事件按收到顺序展示或累积后，能得到请求要求的标记。 |
| 前置条件 | 同 TC-STREAM-001。 |

**步骤：**

1. 要求 Agent 输出 `STREAM_OK=<随机 token>`，避免模型凭通用知识产生假阳性。
2. 按 `onNext` 到达顺序收集所有非空文本，并拼接为最终展示文本。
3. 等待完成后检查拼接结果。

**预期结果：** 拼接文本非空且包含 `STREAM_OK=<token>`；事件收集不因空 delta、元数据消息或
多次发布而抛异常。允许实现将完整回复作为单一事件发布。

**失败诊断：** 单条最终消息含标记而拼接结果不含，通常是消费者过滤/顺序处理缺陷；所有消息均
不含标记时，按模型输出或 SDK 请求封装问题记录。

### TC-STREAM-003：服务中断时订阅以可观察错误结束

| 项目 | 内容 |
| --- | --- |
| 优先级 | P2 |
| 用户目标 | 流式请求遇到不可达服务时，调用方能收到错误并释放等待，不会无限挂起。 |
| 前置条件 | 使用仅对此测试生效的不可达本地端点；不影响正常 Ollama 容器。 |

**步骤：**

1. 创建指向不可达端点的模型配置，订阅 `call(...)`，记录 `onNext`、`onError`、`onComplete`。
2. 在明确的较短测试超时内等待终止。
3. 检查终止类型和已收集事件。

**预期结果：** 触发 `onError` 或公开调用异常，且不会把错误伪装成 `onComplete` 后的空成功；资源
在超时后可释放。

**失败诊断：** 未终止是超时/取消路径风险；正常完成却未返回数据是错误传播缺陷；连接拒绝等网络
异常符合预期，需确认测试端点确实不可达。

## 4. 清理与通过标准

订阅结束后不复用收集容器或 Agent。TC-STREAM-001 为持续 CI 用例；扩展用例应在不同模型和
网络延迟下验证，日志记录事件数量、非空文本摘要和终止信号，但不得输出敏感提示内容。
